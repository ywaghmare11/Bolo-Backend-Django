## 2026-08-29 (5)

- `[BE]` **Phase 15c — multi-format member bulk-import ETL**, `ROADMAP.md` Phase 15, third slice. Branch `feature/platform-admin-bulk-import` off `main` (15a + 15b merged first). `POST /platform-admin/tenants/:tenantId/members/import` — multipart `file`, accepts `.xlsx` / `.csv` / `.json` (CSV + JSON are a bolo-backend-django extension of upstream's Excel-only `api-spec.md` §22 contract, per direct request).
  - **New deps:** `pandas==2.3.3` + `openpyxl==3.1.5` (`requirements/base.txt`, propagates to dev/prod/test via `-r base.txt`). `numpy` rides in as a pandas dependency — **not pinned separately** (pandas already constrains a compatible version). Both are **lazy-imported** inside `apps/platform_admin/etl.py` functions, same "only pay for it on an actual request" pattern as `boto3`/`openai`.
  - **`apps/platform_admin/etl.py`** (new, pure functions, no ORM/Django-at-import):
    - **Extract** — one DataFrame regardless of format. `.xlsx` → `pd.read_excel(BytesIO, engine="openpyxl", sheet_name=0, dtype=str)`; `.csv` → `pd.read_csv(dtype=str, encoding="utf-8-sig")` with a `latin-1` retry on `UnicodeDecodeError` (BOM + non-UTF-8 bytes both handled); `.json` → bare array **or** `{members|rows|data|records: [...]}` → `pd.DataFrame`. Fully-blank rows dropped, `NaN` → `""`, every cell stripped. Unsupported extension / unparseable bytes → `ValidationError(code="INVALID_FILE")`.
    - **Transform** — `_HEADER_ALIASES` maps ~25 real-world header variants to canonical `name`/`email`/`role_level`/`role_label`/`phone`/`can_broadcast`/`preferred_lang`; `_BOOL_TRUE/_BOOL_FALSE` sets coerce `yes/1/true/...` → bool; **vectorised** validation (`str.match(EMAIL_RE)`, `role_level.isin(OrgRoleLevel.values)`, name-present); within-file dedup by email keeping the **last** occurrence (earlier ones become `skipped` errors); **formula-injection neutralisation** — a `name`/`role_label`/`phone` cell starting `= + - @ \t \r` is prefixed with `'`. Whole-file guards raise `INVALID_FILE`: missing a required column, zero rows, over `MAX_ROWS` (5000). One bad row is an `errors[]` entry (`{row, field, reason}`, `row` 1-based counting the header), never a raised exception.
  - **Load** (`PlatformAdminTenantService.bulk_import_members` / `_load_one`) — idempotent `update_or_create` by email, **100 rows per `transaction.atomic()`** so a mid-import failure leaves whole-chunk boundaries. A member already in this tenant is **updated** (User fields + `MembershipRepository.upsert` on the composite-PK `TenantMembership`), not re-created. An email that's globally taken by **another** tenant is skipped with an error (email is `unique=True` on `User`). New repo methods: `UserRepository.get_by_email_or_none`, `MembershipRepository.upsert`.
  - **View** — `PlatformAdminMemberImportView` (`SUPER_ADMIN`-gated, like the other management routes), `request.FILES["file"]` (first multipart endpoint in the project — DRF's default `MultiPartParser` covers it), 5 MB upload cap, `ValidationError(INVALID_FILE)` for missing/oversized file. `tenant_id` 404 checked before the file is touched.
  - **Audit** — `MEMBERS_BULK_IMPORTED` wired: new route-config row (`entity_type "TENANT"`, `actor: "platform_admin"`). New `metadata_response_fields` config key + a 4-line middleware merge folds the response's `{created, updated, skipped}` into `AuditLog.metadata` alongside the operator identity — so "who imported how much into which tenant" is answerable from the audit row alone.
  - **Not built:** department assignment via import (single-add's `departmentId` only), and any tenant-self-service import equivalent (this project has never had one).
  - 30 new tests (`apps/platform_admin/tests/test_platform_admin_bulk_import.py`, **392 total, all green**): ETL unit tests (BOM/encoding, xlsx/json shapes, header aliases, bool coercion, formula neutralisation, per-row + whole-file rejection, dedup, row cap via `monkeypatch`) + API E2E for all three formats (create, idempotent re-import → all `updated`, partial-failure error report, cross-tenant-email skip, no-file/bad-ext 400, unknown-tenant 404, unauth 401, audit row with counts in `metadata`). `ruff check .` / `manage.py check` / `makemigrations --check` clean (no schema change). Not pushed/merged — committed locally on the branch for review.

Built as a factory now (even with one role) so a second role later is a one-line change per view, not a refactor.

An authenticated admin whose role is outside the allow-list now gets `403`, not `401`. `POST /platform-admin/auth/logout` deliberately left `IsAuthenticated`-only (any admin can end their own session). No behaviour change today — there's only one role — but the gate is real and tested.
  - `seed_platform_admin` gained an optional `--role` (choices from the enum, default `SUPER_ADMIN`); Django admin `list_display`/`list_filter` gained `role`.
  - Three existing `issue_admin_access_token(id, email)` test call sites updated to pass `admin.role` (2 in `test_logging_middleware.py`, 1 in `test_platform_admin_tenants.py`).
  - 14 new tests (`apps/platform_admin/tests/test_platform_admin_rbac.py`, **355 total, all green**): the factory in isolation (match/mismatch/`None`/attribute-absent/multi-role allow-list), `role` defaulting + riding in the JWT with tenant claims still absent, and end-to-end enforcement (super-admin passes list + create, unknown-role → `403` on every management endpoint, legacy no-`role`-claim token falls back to the DB column, logout not gated, no-token still `401`). `ruff check .` / `manage.py check` / `makemigrations --check` all clean.
